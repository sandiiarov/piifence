## Direction

Options for the maintainer, not defects:

1. **Precision for short spans.** 142 of the 399 names handed out in the session that ran this audit cover values of 15 characters or fewer, and several of those were not secrets: `ls` permission strings, a byte size, the cipher name in the README, the product's own name prefix, an ordinary hyphenated word and a plan's file name. A few format-agnostic shape guards for short spans could cut these without per-format rules, but every guard costs recall, so each one must keep the suite's recall numbers.
2. **A per-session notice and `/stats`.** With a shared gateway (plan 011), one session's notice can report another session's secrets, because `/stats` and the notice's state file cover the whole gateway. After plan 012, `/stats` could take the session id and the notice could keep its state per session. The gateway would then keep counters per session.
3. **A bypass check.** Nothing checks that Claude Code really sends a session's requests through the gateway; a managed setting or a Bedrock or Vertex configuration might route around `ANTHROPIC_BASE_URL`. A check that fails loudly when a session's requests never reach the gateway would turn a silent bypass into an error. This needs a look at Claude Code's behaviour first (SEC-02).
4. **One gitleaks process per request.** Scanning all of a request's text blocks in one gitleaks run, and mapping findings back to their blocks, would remove most of PERF-03's per-block cost. It adds mapping code to `src/gitleaks.rs`, which plan 010 also changes, so it belongs after 010.
