# piifence

## Purpose

Local redaction gateway for Claude Code that keeps **secrets** (API keys, tokens, passwords, private keys, credentials) out of what is sent to the model provider. Secrets only: personal data is out of scope and is forwarded unchanged. One pipeline, no modes or switches: the secret model, gitleaks and the key rule always run, followed by the guards.

## Ownership

- Library (`src/lib.rs`):
  - `src/model.rs`: cbx-secrets-detector-32M, the previous model, still loadable (ModernBERT, 12 secret labels, BIO tags) on candle with Accelerate. `SecretModel::load(dir)` reads `MODEL_FILES` (`config.json`, `model.safetensors`, `tokenizer.json`, `secrets_config.json`); `predict` errors on text over the model's position limit. Span rules (edge trimming, per-label `min_len` in characters) follow the model's Python reference `cbx_secrets.py` exactly; `bench/models/parity.py` checks that.
  - `src/scrub.rs`: SporeLabs Scrub (ModernBERT 17M, one sigmoid head per type plus `begin`), the default model. `ScrubModel::load(dir)` reads `SCRUB_FILES` (`config.json`, `model.safetensors`, `heads.safetensors`, `tokenizer.json`, `scrub_config.json`); windows (512/384) and decoding follow Scrub's `_model.py`, only `SECRET` spans are returned. `Detector::load` takes one or more model dirs (`PIIF_MODEL_DIR` joined with `:`); a dir with `scrub_config.json` is Scrub, any other is cbx.
  - `src/keyrule.rs`: `spans` (a quoted random-looking value under a secret-named key or block, tracked by indentation), `hex_spans` (bare 32–128 hex unless a nearer hash word explains it), `cue_spans` (a value after a secret word in prose, in many languages, or a lone value under a short secret-naming label line) and `prefix_spans` (`<prefix>_<random>` keys of any provider, mixed case, not Messages API ids, UUID-bearing ids or base64 runs).
  - `src/gitleaks.rs`: runs `gitleaks stdin` with `gitleaks.toml` (the default rules plus the `piifence-*` rules), which is built into the binary (`include_str!`) and written whole to `gitleaks-<hash>.toml` in the cache dir at startup. gitleaks runs in that directory with `--ignore-gitleaks-allow`, so inline `gitleaks:allow` comments and a `.gitleaksignore` where the gateway was started have no effect. `locate` returns every copy of a plain finding's secret, and for a decoded finding (base64, hex or percent) every encoded run on its line; a finding it cannot place, or an unknown decoder, is an error.
  - `src/guards.rs`: `suppress` (every engine: env references such as `$PIIF_SECRET_1` or `os.environ[...]`, `path/file.ext:line` references, the user's `allow` list) and `suppress_model` (model spans also: no letter or digit, stand-ins such as `sk-...` or `***`, under 4 characters, code, and identifiers, hashes, paths, numbers or plain words unless a secret keyword comes right before or on the two lines above).
  - `src/detect.rs`: `Detector::load(model_dir, allow, cache_dir)` and `detect(text)`: the model in 3,000-byte windows with 500 bytes of lookahead, a second model pass on a copy where long tokens glued to non-ASCII text are set apart (`isolate`), the key rule and gitleaks; guards; overlapping spans unioned. `DetectedSpan.source` is `model:<LABEL>`, `keyrule` or `gitleaks:<rule>`.
  - `src/cache.rs`: final detections per text, keyed by SHA-256 of a fingerprint (format, binary stamp, allow list, model files, gitleaks version) plus the text, kept in memory and appended to `<cache dir>/detections.jsonl` (dir 0700, file 0600, compacted past 32 MB). Entries hold offsets, sources and suppression reasons only, never text or values. An unreadable line or a failed write is an error.
  - `src/config.rs`: `$PIIF_CONFIG`, else `~/.config/piifence/config.toml`; one key, `allow` (regexes). No file means no exceptions; an unknown key or invalid pattern is an error. `piifence.toml.example` is the tracked example.
- Gateway (`src/bin/gateway.rs`, binary `piifence-gateway`): see the contract below.
- Launcher (`src/bin/piifence.rs`, binary `piifence`): `piifence claude`, `piifence session-start`, `piifence env`, `piifence nested-claude`.
- Session plugin: `plugin/piifence-session/`, the `SessionStart` (`piifence session-start`) and `PreToolUse` (`piifence restore`) command hooks.
- Notice plugin: `plugin/piifence-notice/` (hooks plus `scripts/notice.py`). `piifence claude` passes the whole `plugin/` folder to `--plugin-dir`, which loads each plugin in it.
- Reveal plugin: `plugin/piifence-reveal/`, a hooks module (`hooks/register.ts`). Its `ui.render` hooks on `AssistantMessage`, `UserMessage`, `ToolUse` (input and output), `ToolResult`, `CommandOutput` and `AskUserQuestion` draw each `$PIIF_SECRET_<N>` name's value, fetched with `piifence env <session> <port>` (session from `ANTHROPIC_CUSTOM_HEADERS`, port from `ANTHROPIC_BASE_URL`). Display only: the transcript and what the model reads keep the names. `PIIF_REVEAL=off` turns it off.
- Installer and scripts: `scripts/install.sh` (macOS; binaries in `$PREFIX/libexec/piifence`, model and plugin in `$PREFIX/share/piifence`, a wrapper in `$PREFIX/bin/piifence` that sets `PIIF_DATA_DIR`), `scripts/fetch-weights.sh <dir>` (pinned revision, SHA-256 checked), `scripts/check.sh`.
- Homebrew: `Formula/piifence.rb`, so the repo is its own tap (`brew tap sandiiarov/piifence https://github.com/sandiiarov/piifence`). It pins the source `revision` and repeats the model URLs and SHA-256 hashes from `scripts/fetch-weights.sh` as resources. Bump `revision` and `version` for a release, and change both files together when the model changes. Same layout as `install.sh`: binaries in `libexec/bin`, model and plugin in `pkgshare`, a `bin/piifence` wrapper that sets `PIIF_DATA_DIR`.
- Tests: `tests/secrets/` (end-to-end suite), unit tests in each module. Bench: `bench/models/`, `examples/model_spans.rs`, `examples/guard_filter.rs`. Results: `docs/model-options.md`. Outside research (other detectors, proxies, papers; sources pinned): `docs/research/`.

## Local Contracts

- **No fallbacks.** A missing file, an unset required variable, an unparsable value, a failed write or a finding that cannot be placed is an error, never a silent default or a degraded mode. Defaults are allowed only for optional settings with one documented value (`PIIF_PORT` 7788, `PIIF_EXIT_WHEN_UNUSED` 10 for a gateway the launcher starts, `PIIF_DATA_DIR` `~/.local/share/piifence`, `PIIF_CACHE_DIR` `~/.cache/piifence`, `PIIF_STATE_DIR` `~/.local/state/piifence`, the audit log path), and a set value that does not parse is an error.
- Build: `cargo build --release` (Apple Silicon, candle with Accelerate, CPU).
- Gateway:
  - Env: `PIIF_UPSTREAM` and `PIIF_MODEL_DIR` required; `PIIF_PORT`, `PIIF_EXIT_WHEN_UNUSED` (seconds; above 0 the gateway exits once no live launcher has held a lease that long), `PIIF_AUDIT_LOG` (`/tmp/piifence-audit.log`), `PIIF_AUDIT_BODY=1` (also log rewritten bodies), `PIIF_CACHE_DIR`, `PIIF_STATE_DIR` (`names/`, and `run/<port>.sock`, the control socket). gitleaks must be on PATH.
  - **Input only, the only mode.** It redacts `POST /v1/messages` and `/v1/messages/count_tokens` and streams the upstream response back byte for byte (no buffering, no SSE parsing, no replacing names back). Other `POST /v1/messages/*` shapes are refused. Fails closed: a request that cannot be fully scanned is answered 502 and not forwarded.
  - Every content block type that can carry text is routed through `redact_block`; a new block type is added there and nowhere else. Thinking blocks and images are never touched.
  - Model context: a `tool_result` is scanned with its tool call in front as a shell transcript (`tool_result_context`): `$ <command>\n` for Bash, `VAR=` for `echo $VAR`, `$ cat <path>\n` for Read, `Tool call: <name> <input JSON>\nTool output:\n` for other tools. Bash-mode output (`<bash-input>` / `<bash-stdout>` tags) gets the same shell context. Only spans inside the text itself are replaced.
  - Sessions: `piifence claude` gives each session a random 32-hex id, which Claude Code sends as `x-piifence-session` (via `ANTHROPIC_CUSTOM_HEADERS`, merged with the user's). A messages request or `/control/*` call without a valid id gets 403. The header is stripped before forwarding. `/stats`, every `/control/` path and the `/health` answer that names the upstream are served only on the control socket `$PIIF_STATE_DIR/run/<port>.sock`, whose directory the gateway creates 0700, because any account can connect to a loopback port; on TCP they get 404 and `/health` leaves the upstream out.
  - Names: every secret becomes `$PIIF_SECRET_<N>`, numbered once per value per session, so history is rewritten identically every turn. Before detection, every known value of the session is replaced with its name in all provider-bound text (audit engine `env`); a value under 16 characters only as a whole token (`WHOLE_TOKEN_BELOW`: no letter or digit of the text may run into its first or last character when that character is a letter, digit, `-` or `_`). A name is written `${PIIF_SECRET_<N>}` when a letter, digit or `_` follows it (`name_token`), so the shell and `piifence restore` read the same name. After detection, `sweep_values` replaces every named value again across the whole request (skipping thinking blocks, base64 sources and top-level `metadata`). `GET /control/env` returns the session's names and values, for `piifence env`.
  - Saved names: the `SessionStart` hook sends Claude Code's conversation id to `GET /control/conversation` (`x-piifence-conversation`). The gateway merges that conversation's stored table (stored names win; a clashing new name is renumbered) and from then on saves it after every change to `$PIIF_STATE_DIR/names/<conversation id>` (default `~/.local/state/piifence`), XChaCha20-Poly1305 with the conversation id as associated data. The key is a Keychain item (service `piifence`, account `names-key`) read and written through `/usr/bin/security` (stdin, never argv), so updates to piifence don't trigger Keychain prompts. Tables untouched for 30 days are deleted at gateway start. Sessions that never bind (the test suite) store nothing.
  - Hardening: binds loopback; rejects requests with an `Origin` header or a non-loopback `Host`; 64 MB body limit; audit logs created 0600; tool input in the model context is cut to 800 bytes on a char boundary.
  - Audit log and `/stats` hold metadata only: field, kind (model label, gitleaks rule or `keyrule`), engine, offsets, name, and a masked first4+last4 `preview`. `/stats` has counters, `by_kind`, `redact_ms_*`, and `recent` first sightings only.
- Launcher:
  - `piifence claude` resolves the upstream from `PIIF_UPSTREAM`, else the shell's `ANTHROPIC_BASE_URL`, else Claude Code settings `env.ANTHROPIC_BASE_URL` (no default provider; a value pointing at our own gateway is ignored). It reuses a running gateway only when `/health` on its control socket reports the same upstream; a port that answers on TCP without that socket is an error, never reused. Before Claude Code starts, it takes a lease (`GET /control/lease` with the session id and `x-piifence-launcher-pid`), and it never stops a gateway: one it started runs with `PIIF_EXIT_WHEN_UNUSED` (10 unless set) and exits once no live launcher has held a lease that long. A 503 answer means that gateway is shutting down, so the launcher waits for it to close and starts a new one. It starts `piifence-gateway` from next to its own real path with `PIIF_MODEL_DIR=$PIIF_DATA_DIR/model`, and refuses to launch Claude Code if the gateway does not become healthy. It passes `--settings` (a 0600 `create_new` temp file with `ANTHROPIC_BASE_URL` and `ANTHROPIC_CUSTOM_HEADERS`, no hooks) and `--plugin-dir $PIIF_DATA_DIR/plugin` (the session, notice and reveal plugins), rejects a user `--settings`, and never edits `~/.claude/settings.json`. The `SessionStart` and `PreToolUse` hooks live in `plugin/piifence-session/hooks/hooks.json`, because a managed policy can drop settings-file hooks while it loads plugins; they read `PIIF_BIN`, `PIIF_SESSION`, `PIIF_SESSION_PORT` and `PIIF_SESSION_NESTED`, which the launcher sets (`hook_env`).
  - Fail closed on missing hooks: a `POST /v1/messages` that offers tools, from a session no `SessionStart` hook has bound, waits up to 15 s (`HOOKS_WAIT`) for the bind and is then answered 400 with `HOOKS_MISSING`, never forwarded. Requests without tools (titles, quota checks) pass.
  - `piifence session-start <session> <port>` returns `VARIABLES_NOTE` as `additionalContext` and appends `eval "$(piifence env <session> <port>)"` to `CLAUDE_ENV_FILE`; it exits non-zero when that is impossible. `piifence env` prints `export PIIF_SECRET_<N>='…'` lines and exits non-zero with an error if the gateway does not answer. It also installs the `claude` shim in `$PIIF_STATE_DIR/bin`, and `piifence env` prints a line that puts that directory first on `PATH`. The shim runs `piifence nested-claude`, which reads the session from `ANTHROPIC_CUSTOM_HEADERS` and the port from `ANTHROPIC_BASE_URL`, and runs the real `claude` (first on `PATH` outside the shim directory, or `CLAUDE_BIN`) with the same hooks, the `SessionStart` one as `session-start <session> <port> nested`, which skips the conversation binding. No lease is taken.
  - `piifence restore <session> <port>` is the `PreToolUse` hook (matcher `*`). For every tool but `Bash`, `PowerShell` and `Monitor`, it replaces `$PIIF_SECRET_<N>` and `${PIIF_SECRET_<N>}` in every string of `tool_input` with the session's values and returns `updatedInput` with no permission decision, so permission prompts still apply. Input without a name is left alone without calling the gateway. An unknown name or a gateway that does not answer exits 2, which blocks the call. So does a bare name that a letter or `_` follows directly (`glued_name`), because a shell would read it as a longer variable name. A backslash that escapes a name's `$` (an odd number of them) counts as part of the name and is replaced with it. For `Bash` and `Monitor` (`SHELL_TOOLS`) it rewrites only `command`, through `piifence::shellfill::fill_command`: names the shell expands itself are left alone, and names it would not expand (single quotes, ANSI-C quotes, quoted heredocs, an escaped `$`) get the value escaped for where they stand; a command whose quoting it cannot follow (unclosed quote, heredoc, `$(` or backtick) is blocked. `PowerShell` is skipped.
  - The note is hook context, not a system-prompt section: an organization's policy plugin (`cc-plugin-sec-default`) skips user plugins' `prompt.compose` hooks; do not work around that. Nothing rewrites transcript rows: only provider-bound input is redacted.
- Notice plugin: metadata only, never raw values. Silent (prints `{}`) unless `PIIF_NOTICE=on`, because piifence is meant to be invisible on screen. `PIIF_GATEWAY_SOCKET` (the control socket, set by `piifence claude`) is required; a gateway that does not answer is an error the hook reports. It reports only values replaced for the first time.
- Never commit a Claude Code test settings file, an auth token or model weights.

## Work Guidance

- Keep the dependency list to what `Cargo.toml` has; justify additions.
- A guard needs a failing suite case or unit test, a `Suppression` reason, and a unit test. Guards decide keep or drop only; they do not move span boundaries.
- Probe the model on a string with `cargo run --release --example model_spans <model dir>` (JSONL `{"text": …}` on stdin, byte spans out).

## Verification

- `scripts/check.sh` runs every check; CI (`.github/workflows/ci.yml`) fetches the model and runs it on every push to main and every pull request. It needs `PIIF_MODEL_DIR` unless given `--no-suite`. A new check is added to the script, not to the workflow.
- `cargo fmt --check`, `cargo clippy --release --all-targets -- -D warnings`, `cargo test --release`.
- `python3 -I tests/secrets/run.py --model-dir <model>` runs the end-to-end secret suite (formats × Claude Code request locations, negatives, and cases mined from real sessions) through the real gateway, one session per case. It must exit 0. Known gaps are listed in `tests/secrets/expectations.json`; a change that fixes one must remove its entry. Baseline 2026-11-11: 1055/1065; 0 false positives on the made-up negatives, 7 known false positives on the mined ones, 3 known leaks (all made-up). `--check-generators` checks each generated format against the gitleaks rules it lists; `--self-test` checks the checks. `tests/secrets/stats_check.py` checks `/stats` and the notice.
- `bench/models/` compares secret models on the suite cases without the gateway (`setup.sh` downloads pinned models into `$PIIF_BENCH_DIR`, default `~/.cache/piifence/bench`; `shootout.py` scores engines; `speed.py` times the Python references; `parity.py` checks the Rust port against `cbx_secrets.py`). Not part of `scripts/check.sh`.
- End-to-end: `piifence claude --version` (smoke) and a real `piifence claude -p ...` run; verify the upstream-visible request has `$PIIF_SECRET_*` names, with `PIIF_NOTICE=on` the Stop notice lists the replacement, raw values appear in no log, and the gateway process is gone after exit.
